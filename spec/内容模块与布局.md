# 内容模块与布局

本文明确 [Agent 转换约定](Agent转换约定.md) 中模块与布局的边界。保存字段见 [文档格式](文档格式.md)；统一外观见 [统一样式](统一样式.md)。模块集按反复出现的结构能力逐步增加，不按论文或出版社列模板。

当前格式以阅读效果为目标。Agent 根据内容自主选择分组、模块组合和语义 HTML 布局，再在阅读器中检查宽度、层级、密度及双语效果。统一样式使这些选择可以稳定执行，不要求所有资料机械使用同一种排列。内部身份仅用于引用与修订，绝不作为默认显示标题或翻译文本。可调整的实例见 [布局范例](../services/workspace/authoring-examples/index.md)，作者字段见 [schema](../services/workspace/authoring-schema.json)。

块可选 `placement: "frontmatter" | "body"`，由 Agent 明确选择归入标题下的作者说明折叠区，或留在正文流中。目前所有前置信息共用这个区域，不是任意页面插槽。缺省时 `rights`、`publication`、`author-details` 进入该区域，其他角色留在正文；显式 `body` 可以覆盖角色默认位置。这个选择只改变呈现分组，不改变内容身份、原稿来源或源/译对应。作者贡献说明可以收在前置信息中，技术脚注仍紧随相关论述；脚注的 `num` 仅用于真实源标记，缺失时不从 ID 猜造。

## 如何选择结构

先识别哪些关系必须一起被理解，再选择模块。原文事实、数据、公式、标记、图注归属、表格关系和可靠阅读次序不能因美化而改变；PDF 的分页、物理分栏和提取块边界不必照搬。

| 内容关系 | 可选安排 | 必须保留 |
| --- | --- | --- |
| 连续论述与章节 | 标准 heading/para，按阅读顺序排列 | 真实层级和论证次序，不把章节藏进一个 HTML 对象 |
| 一张图与独立题注 | figure；确有图文共同布局需要时使用 HTML | 原图、题注和图中标记的归属 |
| 多个子图或相互解释的图文 | HTML 中上下排列、并排或网格 | 每个子图及其说明的对应，窄容器仍按 DOM 顺序可读 |
| 算法步骤及注释 | 列表，或一个 HTML 组合 | 步骤先后、注释关联、代码缩进和换行 |
| 定义与解释 | 相邻段落，或一个语义 HTML 组合 | 定义范围与原始解释；布局不能新增原稿没有的结论 |
| 分组统计结果 | 简单 table，或保留跨度与表头的 HTML table | 数值、真空白、单位、跨度、分组及脚注 |

这些安排可以变化。并排不一定比上下更好；应根据内容长度、关系和桌面阅读区域决定，再检查显示结果。

## 最小模块

| 模块 | 承载内容 | 应保留的关系 |
| --- | --- | --- |
| heading、para | 标题、正文、来源说明、脚注、参考文献 | 阅读顺序、层级、段内链接和强调 |
| list | 有序步骤或无序条目 | 项目身份、顺序及编号 |
| math | 独立公式 | 原 TeX、原编号、来源；行内数学仍放在所在文本内 |
| figure | 一张图及其完整题注 | 图像、题注、子图标签、图中文字及来源 |
| table | 可由规则矩阵完整表达的简单表 | 行列、表头、题注和真空白 |
| html | 需共同布局的复杂对象 | 语义 HTML 中的跨度、多级表头、步骤、代码、图文组合等 |

算法、代码、定理/证明和统计格可以用语义 HTML 表达，不要求立即扩充一套专用 JSON 语法。`role` 用来描述对象，例如 table、algorithm、figure、code；不能作为文章专用组件的路由。自定义语义 role 不会自动获得新的布局或专用样式；遇到未知系统角色的提示时确认其意图，不依赖一个新 role 名称创造能力。

## 布局能力

共同组合能力是上下排列、并排/网格、表格内部排列及对象内部溢出。`layout-stack`、`layout-pair`、`layout-grid` 是系统管理的组合类；并排在窄容器下回到 DOM 顺序。`text-start`、`text-end`、`scalar`、`group-start`、`ruled` 是对齐、短原子和分组线的可选提示。

局部布局可以指定列的相对关系、换行及对齐，不能改变正文语义顺序、把内容隐藏、用绝对定位覆盖页面或自行缩放字体。只有很宽时，优先使用现有表格和对象滚动，不因此升级为 HTML。

顶层 `blocks` 当前是一条阅读序列；上下排布由顺序表达，需要共同排布的局部对象可用一个 HTML 块组合。没有顶层 `group`、任意 `layout` 字段、侧栏插槽或作者自定义折叠组件。HTML 内也不支持文章 h1–h6 标题，目录从标准 heading 块建立。不要填入看似合理但阅读器不支持的字段；若反复出现必须保留独立块身份又共同布局的真实需求，再明确扩展合同。

表头跨列、子图与题注对应、统计量和标准误、算法步骤次序都具有内容含义，必须在 HTML/模块关系中保存。视觉上的边框、阴影、字号不作为这些关系的唯一依据。粗体最佳值使用 strong，斜体与上下标保留语义；原图中的实验组颜色保留在原资源中，不能被主题替换破坏。

## 阅读器拥有的行为

figure、table 和 html 对象通过统一容器获得原位展开、独立宽度调整、局部滚动、批注避让和键盘操作。双语、引用、选区、修订和来源定位使用统一身份。普通正文和公式使用各自的阅读交互；不能把图表的对象控件推定为每一种块都有的能力。作者内容不实现按钮、动画、事件处理或本地存储。

展开与缩放保持字体和图片比例；关闭恢复查看状态，不更改正文 revision。具体行为见 [阅读器页面设计](阅读器页面设计.md)。

## 核对安排是否有效

先处理字段、HTML/CSS、资源和来源诊断，再看实际桌面阅读器：普通与较大字号、正文单独显示及打开 PDF/工具面板后的较窄阅读区域、源文/译文/对照、对象展开及引用返回。确认内容关系仍可见，所有列和步骤可达，图文归属没有因折行改变。这里的窄容器是桌面窗口与面板变化，不要求进行当前范围外的移动端适配。原稿核对和显示检查分别记录，不把布局正确等同于内容忠实。
