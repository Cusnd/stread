# 维护与验证

[设计系统](README.md) · [待统一项](inconsistencies.md) · [设计变更记录](changelog.md)

## 每次前端更新都同步文档

影响样式、布局、文案、控件、状态反馈、动画、输入、焦点或导航的修改，必须在同一改动中更新本目录。不能只在聊天中描述，也不能等到下一次集中整理。

1. **修改前选规则。** 查找对应主题、当前实现入口和待统一项；确认复用哪个现有角色，检查相关页面。
2. **修改时同步主题。** 更新实际受影响的外观、交互状态、源码链接和检查要求。如果只是修复既有规范的实现偏差，更新该主题的差异或核对记录，不伪造一条新设计规则。
3. **登记最终决定。** 在[设计变更记录](changelog.md)追加日期、改动、影响范围、理由、证据和遗留项。不要保留被否定的方案作为当前推荐。
4. **处理关联差异。** 修复后关闭对应待统一项；只修一个入口时说明剩余范围，不宣称全局统一。
5. **交付时给出对应文档。** PR 或本地交付说明列出本次更新的主题，分别报告源码、自动化、浏览器、Electron 或安装包证据。

不影响前端的后端、构建或纯文档修订可在交付说明写明“无界面影响”及原因，不要求凭空改写设计规则。只增加日期、不更新内容或核对记录，不算完成同步。

## 一条组件规范应包含什么

| 必需内容 | 写法 |
| --- | --- |
| 用途 | 操作角色、适用场景、与相近控件的选择边界 |
| 当前基线 | 实际共享组件 / 选择器 / token 的相对链接；必要尺寸即可 |
| 状态 | 默认、悬停、焦点、选中或展开、忙碌、失败、退出中，按组件适用性列出 |
| 交互 | 点击范围、键盘、焦点、滚动、中断、草稿保留等 |
| 场景差异 | 为什么必须不同；影响哪些入口；不要以“当前就是这样”作为唯一理由 |
| 验证 | 相邻页面、边界输入和动态过程；已运行与待核验分开 |

公共组件的规则只维护一份，功能文档引用它。组件迁移或重命名时同时更新源码链接；涉及作者内容、业务语义和历史规格时同步原始合同，不把全部规则复制到这里。

## 按影响范围检查

| 改动 | 最少交叉检查 |
| --- | --- |
| 按钮、颜色、字体或尺寸 | 顶栏入口、Collection 阅读操作、Queue 提交、设置完成；长文案与禁用状态 |
| 输入、下拉或状态选择 | 收起与展开、长选项、搜索无结果、键盘、保存失败；检查真实点击范围 |
| 弹窗或背景 | 设置、Queue 编辑/添加、修订及同层弹窗；关闭按钮、Esc、背景点击、退出中重开 |
| 加载、空态或错误 | Collection / Flow / Queue 首次进入、切换、详情、后台刷新；慢响应和失败 |
| 动画或列表布局 | 连续切换、动画中反向、相邻行、延迟图片、内容滚动；开始前及途中开启减少动态效果 |
| 导航或滚动 | 工作区 → Reader → 返回，保留筛选、选择、展开、位置和草稿；独立面板滚动 |
| 阅读内容 | 普通与 HTML 图表、源文/译文/对照、正文窄容器、对象缩放及来源跳转 |

使用独立测试资料。根据改动检查桌面窗口和较窄窗口，以及 UI 缩放 80 / 100 / 120 三档（当前计算系数分别为 1 / 1.25 / 1.5）；不要把设置的 80% 误当成 CSS 的 0.8 倍。320px / 390px 可用于极端压缩回归，不表示产品范围已扩展为独立移动端设计。

## 怎样记录证据

先查对应测试文件和[开发指南](../../docs/DEVELOPMENT.md)，运行与修改相关的现有测试；新增测试应覆盖真实风险，不逐项复制 CSS 实现。涉及可见变化，检查实际页面的默认、展开和交互后状态；涉及动画，检查中间帧而不只截首尾。浏览器通过不能代替 Electron，构建通过不能代替安装版。

纯文档修改检查相对链接、来源对应、状态描述、Markdown 和 diff 即可，不为了文档更新重跑应用全套测试。若文档宣称某项行为已经验证，必须附本次实际证据；过去的测试脚本只提供可复验入口。

```markdown
### YYYY-MM-DD · 变更主题

- 改动与原因：最终采用的规则，以及要解决的体验问题。
- 影响范围：页面 / 组件；更新的规范链接。
- 验证：实际运行的检查与结果；未覆盖环境。
- 遗留：待统一项编号，或无。
```

根目录和前端 `AGENTS.md`、贡献指南及 PR 模板都指向本流程。这是协作完成条件，不是已经部署的 CI 自动拦截；不能仅因 PR 勾选通过就认为视觉一致性已验证。
