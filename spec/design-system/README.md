# Stread 前端设计系统

这里记录 Stread 当前的界面语言，以及后续修改应遵循的共用规则。目标是让同一种操作在 Collection、Flow、Queue、Reader 和设置中有一致的外观、反馈和操作预期。本文档与前端代码一起维护，不是一次性的效果说明。

初始整理：2026-10-30，源码基线 `51c7386`。本轮依据近期设计反馈与当前源码核对；没有重新执行整套浏览器或 Electron 验收。历史截图、旧原型和过往测试结果不自动成为当前版本的验收证据。

## 共同原则

1. **先确定角色，再选外观。** 同为“主要按钮”不代表每处都刷深色；顶栏入口、表单提交和阅读主操作有不同的上下文。相同上下文则应复用同一规则。
2. **内容优先，层级靠布局表达。** 白灰表面、炭黑文字、紧凑矩形控件、克制的分隔。去掉重复标题、辅助描述和不承担识别功能的图标。
3. **统一到整个操作过程。** 默认、悬停、焦点、选中、忙碌、失败、退出和再次打开都属于组件设计。静态截图不足以检查一致性。
4. **一处改动，检查同类入口。** 改弹窗关闭就同时检查设置和修订；改加载就检查三个工作区；改下拉就检查展开列表，而不只检查收起外观。
5. **保持用户的位置和控制权。** 原生选区、草稿、键盘焦点、独立滚动和 Reader 返回上下文优先于装饰性动画。保存阅读位置不表示完成阅读。
6. **共享实现优先。** 先查现有 token、组件和动作，再新增变体。新变体必须说明已有变体不能覆盖的使用场景，并在本目录登记。

## 如何理解文档里的规则

| 表述 | 含义 |
| --- | --- |
| 当前实现 / 当前基线 | 已对照源码的事实；不等于已完成当前运行环境的视觉验收 |
| 共用规则 / 后续约束 | 今后相关修改必须遵循的设计约定；不能据此宣称旧代码已全部符合 |
| 场景差异 | 有明确职责原因的差异，例如正文排版、工具栏入口与表单提交 |
| 待统一 / 待核验 | 尚未形成统一实现或证据不足；进入差异清单，不作为新的默认样式 |

尺寸表用于定位当前实现，不能当作一个已经完整落地的组件库 API。CSS 有覆盖关系，核对时要读取最终选择器及加载顺序，并在受影响页面检查计算样式。

## 与其他文档的分工

- 本目录是跨页面 UI 规范的入口。业务规则仍以根目录 [AGENTS.md](../../AGENTS.md)、服务合同和对应功能规格为准。
- [统一样式](../统一样式.md)继续负责作者内容与阅读器样式的控制边界，不重复维护一套应用按钮表。
- [连续动效系统](../连续动效系统.md)保留更细的动效实现约束；本目录的动效页负责选型与跨页面核对，两者相关条目同步更新。
- [Collection](../Collection页面设计.md)、[Flow](../Flow页面设计.md)、[阅读器](../阅读器页面设计.md)等功能文档解释场景；旧稿中被替代的页面或产品方向不重新成为现行规范。
- 新决策应在对应主题写清最终规则，再记录变更。若代码仍有差异，登记到[待统一项](inconsistencies.md)，不要静默把实现偏差改写成规范。
