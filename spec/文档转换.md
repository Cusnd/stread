# 文档转换

> 本页保留产品约定及带日期的设计背景。早期研究稿、截图和个人待办不随公共源码发布；历史验证描述不代表当前发布包的验收结果。当前范围以根目录 AGENTS.md、现行服务合同及本仓库代码为准。

当前实现采用 Agent 主导的作者提交流程。工具提供原文件、资源、目标格式、编译诊断及保存能力；Agent 负责理解与组织原文、自主选择分组和布局、恢复公式与图表关系、核对来源和呈现并修复问题。解析器/OCR 可以预填数据，粗提取不能直接代表完成转换。服务本身不选择或调用 AI 模型。

执行入口是 [作者指南](../services/workspace/authoring-guide.md)，格式责任见 [Agent 转换约定](Agent转换约定.md)，字段限制见 [作者输入 schema](../services/workspace/authoring-schema.json)。Agent 提交 `reader-authoring-1`；工具生成阅读器和 MCP 消费的 schema 2 文档、稳定身份、文本/引用索引及翻译指纹。Agent 不需手工拼装运行时数据。

[模块与布局](内容模块与布局.md) 和 [统一样式](统一样式.md) 分别定义内容表达能力与呈现边界。Agent 在转换时确定适合内容的安排，阅读器在打开时按保存的结构稳定呈现。这里的确定性不限制每份文档的分组和组合选择。普通块与语义 HTML 可以混用；不把整篇文章塞进 HTML 以绕过章节、来源和局部修订。

2026-10-17 的初版草案曾把转换选型与端到端实现列为待定；2026-10-21 起已明确采用上述 Agent 提交方式，旧的“转换服务自行选择模型后直接产出”设想已废止。保留原件、独立正文编辑器取消、后续纠错与用户补充通过 [MCP 文档修订](MCP文档修订.md) 的决定不变。

## 最小流程

原始文件上传到工作台后，MCP 向获授权 Agent 提供原件、目标格式和验证要求。Agent 提交符合约定的作者输入及资源绑定，由服务编译、校验并原子保存。阅读器消费最终结构化文档。

1. 用户上传原始文件，工作台保留原文件并取得可定位的文件标识。
2. 获授权 Agent 取得 `reader-authoring-1` 约定和原文件访问地址。页面上传入口保留原件并提供可复制的转换请求，不假装已派发 Agent。
3. Agent 阅读原稿，可借助解析/OCR/既有核对材料，按可靠阅读顺序编写内容模块、公式、语义表格、资源及来源坐标，并选择合适的分组、图文组合和局部布局。已有译文可复用，但须保留对应关系和核对记录。
4. Agent 上传作者输入 JSON 和图片资源，通过文件 ID 绑定相对路径，创建实时草稿预览。工具检查作者字段并执行编译、资源/hash/页码/结构校验，返回具体诊断；Agent 对照原稿核对并在真实桌面阅读器检查内容和布局。修订通过 `previousPreviewId` 继续同一草稿，保留可确认的身份；失败更新保留旧显示并记录错误，修复后才可发布。验证和预览操作以 [作者指南](../services/workspace/authoring-guide.md#tools) 的当前接口为准。
5. 结构、内容与呈现符合请求后，Agent 提交已检查的最新快照 ID、摘要和内容/布局/交互核对记录。服务在事务中发布该冻结结果，保留精确作者输入、身份登记、索引、资源和检查报告，不重新编译为另一份候选。相同请求 ID 不重复导入；发布成功返回阅读器地址，失败不发布半份文档、不覆盖旧文档。核对记录必需，上传截图等证据及 PDF 导出可选。

这里的“非结构化”指输入尚未符合工作台的内容模型。已保留一个文件不等于服务能自动理解它；某个 PDF 样本通过也不证明扫描件、任意复杂图表或其他文件类型均能正确转换。

## 分工

| 部分 | 职责 |
| --- | --- |
| MCP | 提供转换工具的调用入口、参数说明和结果。 |
| Agent | 按目标格式理解与组织原文、选择模块与布局、修复提取问题、核对公式/表格/数字/来源及真实呈现；可在自身环境使用解析/OCR 辅助，根据诊断迭代作者输入。 |
| 转换服务 | 提供原件与资源、编译作者输入、生成身份/指纹/索引、验证结构与资源并原子发布；不执行自动提取/OCR 或后台转换任务。 |
| 阅读器 | 稳定执行 Agent 保存的语义与布局，统一字体、主题、留白和交互，并与可靠原页来源对应。 |
| ChatGPT 或其他 Agent 客户端 | 调用上述转换与验证工具、提交作者输入，并通过 MCP 按用户指令读取、修订资料或保存洞见；作者输入作为文件提交，不要求在聊天正文粘贴全文。 |

取消内置 AI 聊天的决定保持不变。转换服务的实现选型独立于阅读界面，不因此增加 AI 面板或模型选择界面。

## 结果要求

- 新作者输入须符合可执行 schema；拼错字段或不支持的布局不能当成已实现。已有存储文档的读取与局部修订继续保留未改的内容、ID 和未知可选字段。阅读器能呈现，MCP 能准确读取并局部修订；不能只以“返回了一段文字”“JSON 能解析”或“能在浏览器显示”作为完成标准。
- 保留样本所需的标题、段落顺序、公式、表格和图片，并让内容引用的资源可被加载。
- 按 [双语对照](双语对照.md) 保留原文与已有译文；翻译不覆盖原文，部分译文允许保存且明确标识缺译。是否生成新译文是明确的处理选项，不能把导入默认等同于自动翻译；译文保存须校验其来源指纹。
- 保留文章与原文位置的对应关系，使用文档 `id`、内容 `revision`、稳定块 ID 与来源位置，使后续 MCP 读取、洞见定位和 [PDF 双向同步](阅读与PDF双向同步.md) 指向同一内容；坐标与多区域规则见 [文档格式](文档格式.md)。
- 结构与资源校验在保存结果时执行。内容是否漏段、公式数字是否准确，需要对照原文件验证，不能用结构校验代替。
- 转换以还原和组织原文为目标；讨论、解释与问题合集仍按用户主动保存的规则管理。

## Skill 与实现范围

初版不将 Skill 设为必需依赖。工具说明交代如何调用，输入输出约定说明接收和返回什么，转换实现与校验负责稳定产出。

若以后出现确实需要复用的跨工具操作流程，再考虑用 Skill 封装；不预先建设 Skill 分发、多模型适配或通用 Agent 编排系统。当前上传、校验与发布是明确的请求/响应接口；长任务或异步调度能力需另有实际需求，不从现有流程推定。

## 验收

2026-10-23 当前入口：`get_authoring_contract` 返回格式及指南/示例；`query_uploaded_sources` 用顶层 `action:list/get` 查找原件；`validate_authoring` 提供结构诊断；`create_authoring_preview` 编译并冻结候选；`inspect_authoring_preview` 用 `target:draft/preview` 检查实时草稿或指定快照；`publish_authoring_preview` 按已核对的 hash 事务发布；`read_resources` 用 `kind:authoring_artifacts` 下载作者输入、身份登记、报告和索引。这里只使用当前 32 工具目录，旧名称与参数不兼容；完整参数见 [MCP 工具合同](../services/workspace/mcp-management.md)。HTTP 路由见 [服务说明](../services/workspace/README.md)。UI 保存原件并复制 Agent 请求，刷新后恢复，不隐式派发模型。

同日按用户决定退役旧自动提取链：移除 `convert_document`、`get_conversion`、`cancel_conversion`、对应 HTTP 转换接口、后台调度与启动恢复，以及服务内专用提取/OCR 实现。正式 Agent 草稿流程和共享 PDF 页面信息、原页渲染、来源匹配继续保留。既有文章、原件、洞见及历史转换记录保留，历史未完成任务不再自动执行。外部 Agent 可自行使用解析器/OCR 辅助，提交前仍须核对内容。

每份待验收文档应完成“上传原件 → Agent 取得格式与测试要求 → Agent 整理作者输入与布局 → 草稿预览、报错与修复 → 原稿与真实阅读器核对 → 发布同一冻结快照 → MCP 按目标读取”。独立记录提取辅助、Agent 修订、结构/资源校验、原稿核对和浏览器行为；不把格式通过、坐标存在或进程成功当作全文转换质量证明。历史样本不能代替新增草稿流程的验收；真实外部账号连接与当前本地 MCP 验证分别陈述。

实施事项见 文档处理与阅读器协同设计 与 MCP 协作待办。后续阅读问答与保存规则见 [ChatGPT 与 MCP 协作](ChatGPT与MCP协作.md)。
