# 双语对照

## 同一内容，两种文字

原文保存在已有的 `text`、`caption`、`head`、`rows` 等字段中。译文保存在同一对象的可选 `translations` 下，以实际目标语言为键。单语文档不需要新增空字段；双语也不另建一份独立的 `blocks`。

```json
{
  "id": "p_1",
  "type": "para",
  "language": "en",
  "text": "The expected value is one.",
  "translations": {
    "zh-CN": {
      "text": "期望值为一。"
    }
  }
}
```

此例只展示对照结构，省略来源指纹的译文会显示为“来源版本未确认”。正常新译文保存必须带下文定义的 `source_hash`，完整示例见 [双语文档样例](../prototypes/insight-composer/public/articles/attention-is-all-you-need/document.json)。

原文与译文共用 `id`、段落顺序、公式编号和原页位置。对照呈现为上下排列还是并列属于视图选择，不在正文中存放两套位置。结构可以容纳多个目标语言，阅读时选择其中一种与原文对照；不因此要求首版制作同时显示多种译文的界面。

`origin: "user"` 的补充块仍可保存自己的原始文字与译文，但两侧均须说明是用户补充，没有 PDF 原页位置。切换语言不改变内容来源；原页联动见 [阅读与 PDF 双向同步](阅读与PDF双向同步.md)。

## 哪些内容可以翻译

`translations[目标语言]` 是一个对象，保存允许翻译的字段和可选 `source_hash`。译文内部不再放 `translations`；不允许覆盖 ID、类型、来源、章节层级、编号、顺序和资源路径。各位置的载荷如下。

| 所在位置 | 可翻译字段 | 配对规则 |
| --- | --- | --- |
| 文档 `meta` | `title` | 原文标题与译文标题对应；作者身份、日期等共用。 |
| `heading`、`para` 块 | `text` | 同一块保存对应文字；不能把译文作为新的正文块追加。 |
| `list.items` 中的每个列表项 | `text` | 用列表项 ID 对应，列表块本身不另存一套译文 `items`。插入、移动列表项不改变已有项目的身份。 |
| `table` 块 | `head`、`rows`、`caption` | 原表保持不变；译文矩阵与对应原矩阵的形状必须一致，按行列坐标配对。 |
| `figure` 块 | `alt`、`caption`、`image_text` | 共用原图 `src`。图中文字译文可以独立显示，不默认重绘或替换图片。 |
| `math` 块 | 可选 `tex` | 默认共用同一份公式，不要求生成重复译文。仅当公式含需要翻译的自然语言标签时保存目标版本，数学符号和关系须核对一致。 |
| `html` 块（schema 2） | `html` | 共用块 ID 与 CSS；内部稳定节点 ID 表示配对。结构相同可格/段内对照，否则整块对照；相同内容共享显示仍保留两种语言的引用地址。 |

目标语言键例如 `zh-CN`、`en`；同一目标使用统一代码，不能同时以 `zh`、`中文`、`Chinese` 重复登记同一份译文。当前示例统一使用 `zh-CN`。语言声明属于数据，不由当前界面语言推断。

原文语言依次从列表项、块、`meta.language` 继承。存在译文时必须声明实际源语言，无法识别时明确为 `und`。普通单语原文可以暂不声明。目标键不能是 `source`，该值保留给引用中的原文标识；同语言改写不混入本轮翻译模型。

## 不完整译文与修改

- 可以只翻译一部分块或列表项。不要求整篇翻完才能保存或开始阅读。
- 缺少目标字段表示尚未翻译。译文模式在该位置显示带“未译”标识的原文；对照模式保留原文，并明确该位置没有译文。不能静默显示原文却把它标成译文。
- 已提供的字符串不能用空字符串代表“未译”；缺译用省略字段表达。表格译文的 `head`、`rows` 可分别省略，但一旦提供某个矩阵就要保存完整、同形的矩阵，不用 `null` 单元格组成稀疏补丁。数字、符号等不需翻译的单元格原样保留。
- 原字段本身可为空字符串的表格单元格或文字槽位，允许译文对应为空；不能以此删掉非空原文内容。
- 修改译文只更新选定语言的载荷，原文保持不变；正常正文保存依然递增文档 `revision`。
- 原文更新后保留已有译文，并根据来源指纹显示“原文已更新，译文待核对”。不能自动删掉旧译文，或更新指纹把旧译文伪装成已经匹配新原文。

缺译、来源版本未确认和原文已更新是不同情况。指纹匹配只说明译文基于哪份源内容，不证明翻译质量正确。

## 来源指纹

新译文使用 `source_hash: "sha256:…"` 记录翻译时所读原文的指纹。该值由读取原文的一方计算并随源内容返回；译文回写必须携带当时的值，服务校验仍匹配当前源内容才接受。没有指纹的历史导入可以保留和展示，但须标明来源版本未确认，不能直接认定为最新译文。

不另外保存一个容易失真的 `is_stale` 布尔值。需要显示时重新计算当前源内容指纹：缺少旧指纹是未确认，不相等是待核对，相等是来源匹配。更新文档其他段落不会让这个译文失效；文档 `revision` 仍用于整份文档的写入冲突检查。

为避免各语言实现对对象键排序理解不同，指纹输入使用固定顺序的数组。以继承后的源语言为 `L`，不存在的可选字段以 JSON `null` 参与计算，已经存在的空字符串保持空字符串。各类输入为：

| 对象 | 指纹输入数组 |
| --- | --- |
| `meta` | `[L, "meta", title]` |
| `heading` | `[L, "heading", text]` |
| `para` | `[L, "para", text]` |
| 列表项 | `[L, "list_item", text]` |
| `table` | `[L, "table", head, rows, caption或null]` |
| `figure` | `[L, "figure", src, alt或null, caption或null, image_text或null]` |
| `math` | `[L, "math", tex]` |
| `html`（schema 2） | `[L, "html", html_profile, semantic_tree]`；树的规范化及语义属性见 [HTML 约定](自定义HTML内容块.md)，CSS/class 不进入指纹。 |

将数组序列化为紧凑 JSON，使用 UTF-8、无 BOM、无额外空白、不作 Unicode 规范化。字符串中的引号、反斜杠和控制字符按 JSON 转义，其余 Unicode 字符原样编码，不转义 `/`；常用控制字符使用 `\b`、`\t`、`\n`、`\f`、`\r`，其他 U+0000–U+001F 用小写十六进制 `\u00xx`。拒绝未配对代理码元。计算 SHA-256 后，用 `sha256:` 加 64 位小写十六进制表示。此规则只针对上述由数组、字符串和 `null` 构成的输入，不另建通用 JSON 规范化系统。

指纹覆盖一个可翻译对象的源载荷。表格行列变化会使该表已有译文待核对；第一版不保证在任意表格重排后自动迁移旧单元格译文。位置数组、排版设置、洞见以及无关扩展不参与指纹。

## 双语对照与引用

首版必须能表达并验证三种阅读方式：原文、选定语言的译文、原文与该译文对照。模式、目标语言与前后顺序属于阅读偏好，不改正文内容或 ID；切换后保持阅读位置。

第一版的对应粒度为内容块、稳定列表项和未改结构的表格单元格。翻译可以调整句序和表达，不要求两种语言句数一致；不按相同字符偏移强行匹配句子。逐句联动或跨段多对多对齐需要额外的已验证映射，留到实际有需要时再定义；没有映射时只定位到对应块。

带具体文字的洞见和 MCP 引用，在文档 ID、版本、块 ID 之外，还记录：

- `variant`：`source` 表示原文，目标语言代码如 `zh-CN` 表示该译文。
- `field`：例如 `text`、`caption`、`image_text`、`head`、`rows` 或 `tex`，明确摘录来自哪个载荷。
- 列表项增加 `item_id`；表格单元格增加从 0 开始的 `row` 和 `column`，并用 `field` 区分表头与正文。
- HTML 节点使用 `field: "html_text"` 与 `node_id`，范围基于该语言的规范化文本视图；旧表格坐标迁移须有显式映射并保留原摘录。
- `quote`、`prefix`、`suffix` 取自被引用的那一种文字；表格坐标只在相应文档版本和结构下使用，不能盲目沿用到重排后的表。

切换语言不把一条批注复制成两条，也不修改它原本引用的语言。引用的文字不在当前视图时，可回到对应语言与块位置；对侧最多标示关联块，不声称找到同一精确句子。MCP 返回的文字须标明源／译语言及译文是否缺失、未确认或待核对。

## 与转换、修订和现有参考的关系

当前默认转换流程由外部 Agent 完成原文整理和完整中文翻译，并通过既有作者稿预览、核验与发布保存。Reader 不内置模型调用或后台自动翻译服务。只有明确的仅原文请求才跳过翻译；已有双语内容始终保留两侧。部分译文和缺译状态用于反映进行中的工作，不降低默认交付要求。

原文纠错、译文修订和用户补充均通过 [MCP 文档修订](MCP文档修订.md) 处理，不为双语另设正文编辑器。源语言或源载荷变化后按上述指纹判断译文状态；单纯来源位置或排版变化不使译文过期。

双语模式按本项目的原文、目标语言及来源指纹工作。外部格式导入若缺少原表头或其他原文内容，必须报告并从原文件核对，不能假装两侧都完整存在。

示例和静态检查不能代替实际读写与界面验证。验收至少覆盖部分翻译、MCP 原文纠错导致译文待核对、译文修改不覆盖原文、列表插入不串位、表格双语保留、引用的语言与字段定位、用户补充来源，以及切换模式后的阅读位置与 PDF 对应保持。
