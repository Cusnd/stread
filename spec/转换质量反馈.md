# 转换质量反馈

2026-10-27：质量反馈提供具体问题、精确预览绑定和未完成事项。新调用者默认填写精简的 `reader-quality-review-3`；生成、复审和修复方法由 Agent 决定。保持现有 32 工具及文件/预览/发布接口，操作见[作者指南](../services/workspace/authoring-guide.md)。

## 结果的含义

| 层 | 证据与边界 |
| --- | --- |
| 结构/资源 `structural_resources` | 服务检查格式、资源/hash、身份、链接、公式语法和来源范围；不能证明语义或裁图保真。 |
| 原稿保真 `source_fidelity` | 独立审阅者先读原件，对照完整相关内容、数字、公式、图表及关系。 |
| Reader 显示 `reader_visual` | 实际检查真实 Reader，按内容选择合适的宽度、语言模式及显示状态。 |
| 阅读可用性 `usability` | 核验译文语义、导航、来源/引用、对象展开与溢出内容可达性。 |

结果继续区分 verified、failed、unverified、not_applicable。v3 的后三层由同一份全范围审阅声明投影，不要求重复填写三份总结，也不表示服务分别执行了三次核验。空问题列表、结构 PASS 或成功打开第一页均不等于完成。

`observations.translation` 返回可译字段数、缺译和原译文相同字段的位置。纯公式、数字和原图共享；相同自然语言字段由审阅者判断是否是应保留的姓名/标识或未翻译正文。v3 不要求逐字段例外表，默认缺译仍阻止发布。仅原文或其他目标语言必须来自当前用户的明确要求。

## 一份复审记录

服务返回未核验模板，预填准确候选 ID/hash；原件与完整/受影响范围由服务计算。调用者填写真实且不同的生成者/审阅者会话 ID、原始启动证据 IDs、审阅状态、范围/结果说明、是否先读原件和实际检查 Reader，以及支持材料和问题。

`verified` 覆盖服务选定的全部范围，不能自行缩成首屏或方便检查的对象。身份与实际启动记录是独立复审的必要证据；服务验证文件及声明关系，不把外部宿主的身份声明升级为认证。不能启动独立审阅者或不能检查 Reader 时保留候选并明确待办。

不要求额外的原件清单 JSON、运行 JSON、时间戳表、逐块覆盖数组或重复的分层总结。普通原件笔记、审阅日志和截图可以作为支持文件。报告及所有支持文件须经现有上传工具保存并同时附在发布的 `review.evidence_source_ids` 中；报告不能证明自己或互相证明。格式与限制见[复审提交说明](../services/workspace/conversion-workflow.md)。

## 问题和修复

问题保留稳定 key、检查层、严重性、状态、期望/实际、证据和复查建议；按需定位到作者 key、块、列表项、表格单元、HTML 节点或原页。修复后复查新候选，已解决问题需要该候选的证据。失败报告及未解决阻塞项不能被附加 PASS 隐藏。

发布保留精确 hash、最新草稿、失败更新、资源、版本和回执检查。缺译、缺少完整独立复审或真实 Reader 检查时，服务返回具体待办及恢复入口。报告是冻结候选上的派生结果，不改写候选、manifest 或历史证据。旧 v2 报告继续按原有严格协议处理；历史 v1/文字及生成者自评不能单独完成发布。
