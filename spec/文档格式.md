# 文档格式

> 本页保留产品约定及带日期的设计背景。早期研究稿、截图和个人待办不随公共源码发布；历史验证描述不代表当前发布包的验收结果。当前范围以根目录 AGENTS.md、现行服务合同及本仓库代码为准。

本文定义**持久化与消费者格式**，用于阅读器、存储、MCP 修订和兼容处理。执行转换的 Agent 从 [作者指南](../services/workspace/authoring-guide.md) 和 [作者输入 schema](../services/workspace/authoring-schema.json) 开始，提交 `reader-authoring-1`；工具编译成本格式，自动生成身份、索引和指纹。不要把本页的 `id`、`revision`、`schema` 或翻译 `source_hash` 抄入作者输入。

当前格式采用结构化标准块与语义 HTML 的混合方案，新作者输入输出 `schema: 2`。标准块沿用 schema 1 的载荷与语义；`html` 块见 [自定义 HTML 内容块](自定义HTML内容块.md)。既有 schema 1 文档继续读取，不原地重解释字段。Agent 可选择分组与局部布局，阅读器按 [内容模块与布局](内容模块与布局.md) 和 [统一样式](统一样式.md) 稳定执行。

版本背景：2026-10-17 的 schema 1 草案建立了有序内容块与双语字段，2026-10-18 增加 schema 2/HTML。现在已经有本地阅读器、HTTP/MCP 校验与发布以及真实样本验证；具体范围见 [文档转换](文档转换.md#验收)。这些事实替代早期“尚未完成实现或端到端验证”的状态描述，不代表任意 PDF 转换质量已验收。影响正文理解的后续变化仍遵守下文版本规则。

## 采用的结构与复用边界

一篇文章的正文保存为 `document.json`，外部图片和原始文件按相对路径引用。`blocks` 数组决定阅读顺序，每个块有稳定 ID；块内使用文字和少量行内标记，公式、表格和图片使用明确字段。

这是一份供转换、保存、阅读器和 MCP 共同使用的内容约定。独立正文编辑器已取消；纠错和用户补充通过 MCP 修改这份结构，行为见 [MCP 文档修订](MCP文档修订.md)。

| EasyRead 的做法 | 初版处理 |
| --- | --- |
| JSON 外壳、顺序排列的 `blocks`、块 `id` 和 `type` | 沿用。 |
| `heading`、`para`、`list`、`math`、`table`、`figure` | 沿用类型和主要载荷；公式仍用 `tex`，表格仍用二维数组，图片仍用 `src`。 |
| 正文 `en`／`zh`、题注 `caption_en`／`caption_zh` | 原文统一用 `text`、`caption`；译文放在同一对象的 `translations` 中，以实际目标语言为键。单语时省略译文，对照规则见 [双语对照](双语对照.md)。 |
| 块的 `page`、`box`，另存的 `layout.json` | 来源位置统一到块的可选 `source` 数组，支持跨页和同页多个区域；没有分页的来源不编造页码。 |
| `schema: 2` | 两个项目的 schema 编号彼此独立。本项目用自己的 `format` 和 schema 1/2 合同，不把 EasyRead schema 2 文件视为直接兼容输入。 |
| `reader.json`、`discussion.json`、`chat.json` | 不放入正文格式；洞见、阅读状态与正文分开，聊天继续保留在外部 ChatGPT。 |

复用的是内容模型与相关处理思路。本项目已有自己的阅读器与编译流程；EasyRead 渲染器不能原样读取本格式，也不因保留参考项目而声称完成 EasyRead 文件导入适配。

## 文档外壳

| 字段 | 要求与含义 |
| --- | --- |
| `format` | 必填，固定为 `"continous-reader"`，识别本项目的文档格式。 |
| `schema` | 必填整数，已有标准块文档为 `1`；增加 HTML 正文能力的新版本为 `2`。表示格式规则的版本，不能用内容 revision 代替。 |
| `id` | 必填，工作台分配的稳定文档 ID；不使用标题或文件名作为身份。 |
| `revision` | 必填，从整数 `1` 开始；服务在原文、译文、元数据或来源映射变更保存时递增，表示这篇内容的版本。 |
| `meta` | 必填对象，`title` 为原文标题的非空字符串；可选字符串 `language`、`authors`、`date`，以及标题的 `translations` 对象。日期不明时保留来源写法，不猜测精度。 |
| `source` | 可选，原始文件信息：`path` 为资源相对路径，`media_type` 为文件类型，`sha256` 为原文件摘要。上传转换所得文档必须填写真实来源；独立编写的结构示例可以省略。 |
| `blocks` | 必填数组；正式转换结果至少有一个块。数组顺序就是正文顺序，不另存一份排序字段。 |
| `extensions` | 可选对象，只在实际有扩展数据时出现；规则见下文。 |

`schema` 与 `revision` 互不代替。例如，按同一套格式修改一段文字，`schema` 仍为 `1`，`revision` 从 `1` 变为 `2`。问题、批注、阅读进度和字体设置的变化不增加正文的 `revision`。

`meta.language` 如 `zh-CN`、`en`，表示原文的主要语言，不随阅读器切换译文而改变；不能从字段名推断语言，不能把未知语言一律当作英文。需要时，块及列表项可用可选 `language` 覆盖继承的原文语言。具有译文时须明确源语言；确实未知时使用 `und`。

## 内容块

所有块都有非空字符串 `id` 和 `type`，可选 `source`、`origin`、`language` 与 `extensions`。可翻译对象另支持正式字段 `translations`，允许位置和载荷见 [双语对照](双语对照.md)。ID 在文档内唯一且不随修改和移动而变化；原文和译文共用同一块身份，不把数组下标、章节号或正文哈希当作长期 ID。

| `type` | 载荷 | 约定 |
| --- | --- | --- |
| `heading` | `text`，`level`，可选 `num` | `level` 为 1–6，表示文章内部标题层级；页面题头由 `meta.title` 提供。`num` 保留来源章节号。 |
| `para` | `text`，可选 `role`、`cont` | 普通段落。`role: "abstract"` 可标识摘要，`cont: true` 可保留公式后的续句。 |
| `list` | `ordered`，`items: [{id, text}]` | 首版为平级列表。每项有稳定 ID，避免插入一项后原有批注因下标变化错位。 |
| `math` | `tex`，可选 `tag` | 行间公式；`tex` 不包 `$$`，`tag` 保留原编号字符串。 |
| `table` | `head`、`rows`，可选 `align`、`caption`、`caption_pos`、`num` | `head`、`rows` 都是二维字符串数组，表头可为空；有内容的行列数一致。`align` 如 `lrr`，长度须等于列数；`caption_pos` 为 `above` 或 `below`，省略时在下方。 |
| `figure` | `src`，可选 `alt`、`caption`、`num`、`image_text` | `src` 指向已保存的图片资源；`image_text` 可保留图中文字抽取，不能替代图片本身。 |
| `html`（schema 2） | `html_profile`、`html`，可选 `css`、`role`、`num`、`fallback`、`reference_mappings` | 一个复杂对象的静态 HTML 与局部 CSS。文字索引从 HTML 生成，内部节点持久身份、源/译配对及检查见 [专门约定](自定义HTML内容块.md)。 |

列表项 ID 与块 ID 在同一篇文档内不重复。段落、标题、列表项和表格单元格的文字都必须是字符串；不以数字类型保存表格数值，避免丢失小数位、百分号或脚注标记。

上述载荷保存原文。译文只存允许翻译的载荷，不复制块 ID、顺序、来源位置和结构信息。列表按稳定列表项 ID 配对；表格译文保留与原表相同的行列结构，不能覆盖原表。

`origin` 标识正文块的内容来源：省略或 `"source"` 表示来源内容，`"user"` 表示用户要求加入正文的补充。纠正抽取错误不改变来源身份。用户补充使用独立块和新 ID，不填写块级 `source`；阅读器及 MCP 必须保留和呈现来源区别，不能把补充混进来源段落。列表项继承所在块的来源身份，补充列表单独成块。独立人工格式样例不作为真实来源证据。

正文脚注、参考文献先用普通标题、段落或列表表达，并保留它们自己的 ID。引用可用显式内部链接，例如 `[1](#ref_1)`；目标是块或列表项的 ID。不另建一套仅为学术论文服务的必填顶层字段。

块可选 `placement: "frontmatter" | "body"`，用于 Agent 明确选择呈现分组。`frontmatter` 进入标题下可展开的作者说明区域，`body` 留在正文；省略时沿用阅读器的已有角色默认值。它与内容身份、源/译关系分离，译文不得单独覆盖；只调整分组不使译文过期。`role: "footnote"` 的可选 `num` 表示真实原稿编号，不显示“脚注 + ID”或从内部身份推造标记。已在正文中保留的 `*、†、‡` 不重复增加标记。细则见 [内容模块与布局](内容模块与布局.md)。

schema 1 的标准块不声称支持合并单元格、嵌套列表或任意排版。schema 2 可由显式 HTML 块承载复杂结构，不要求先为每一种特殊布局新增专用 JSON 类型。无法准确识别或超出 HTML profile 的结构仍须报告问题并保留原文件；原图供核对，不能把截图预览标成“结构化转换已完成”。

## 文字、公式与资源

文字使用明确的有限标记：`**粗体**`、`*斜体*`、行内代码、普通链接、内部 ID 链接和 `$...$` 行内公式。段落允许带语言标签的 fenced code，先沿用 EasyRead 的做法，不为暂未需要的代码块建立额外类型。

段落中的换行使用 `\n`，独立段落用不同的 `para` 块。完整标题、列表和表格不再重复编码到一个大 Markdown 字符串中。标准块的文字字段不接受原始 HTML；自定义 HTML 必须使用 schema 2 的显式 `html` 类型，不借少量行内标记混入全部 Markdown 或网页代码。

公式保留 TeX 字符串。JSON 中反斜杠必须正确转义，例如 `"\\frac{a}{b}"`；解析后字符串应为 `\frac{a}{b}`。转换结果应检查控制字符和公式可渲染性，不能仅检查 JSON 能否解析。

`source.path` 与 `figure.src` 都相对于该文档的资源根目录，使用 `/` 分隔，不使用绝对本机路径、`..` 或会失效的临时签名 URL。云端服务负责把相对路径解析为当前可访问的资源地址；具体存储供应商和预览图片缓存不成为格式前提。

已引用图片的内容保持不可变；替换图片使用新的资源路径并保存新的文档版本，避免同一个 `src` 背后的内容悄悄改变。原始来源文件同样保留可核对的原始版本。

## 来源与引用

文档级 `source` 指向原始文件。块级 `source` 是位置数组，每项可有从 `1` 开始的实际页序 `page` 和归一化坐标 `box: [x0, y0, x1, y1]`；`box` 必须同时有 `page`。坐标相对于按有效页面边界和旋转方向显示后的原页，左上为原点，值在 0–1 内，且 `x0 < x1`、`y0 < y1`；没有可靠坐标时只记录页码。原页与正文联动及降级行为见 [阅读与 PDF 双向同步](阅读与PDF双向同步.md)。

```json
{
  "id": "b_cross_page",
  "type": "para",
  "text": "跨越两页的同一个段落。",
  "source": [
    {"page": 1, "box": [0.1, 0.8, 0.9, 0.95]},
    {"page": 2, "box": [0.1, 0.1, 0.9, 0.2]}
  ]
}
```

同页跨栏也可用多个区域表达，区域按来源内容的顺序排列。第一版不根据不同页的坐标生成一个虚假的总框；块顺序由 `blocks` 决定，来源数组只说明这个块对应原文件哪些位置。非分页来源可省略块级位置，仍能通过文档来源与块 ID 定位到结构化内容；网页选择器等细定位待实际输入类型确定后再扩展。用户补充不继承相邻来源块的 PDF 位置。

MCP 与洞见使用 `document_id + revision + block_id` 识别引用，必要时增加 `item_id`、摘录 `quote` 和上下文 `prefix`／`suffix`。具体文字还须记录原文或哪种译文的 `variant` 与字段位置，见 [双语引用规则](双语对照.md)。文章级问题不要求 `block_id`；跨块引用保存多个目标。完整洞见对象、引用链接和工具参数另行定义，不混入正文。

重新排版不改变 ID。重新转换时，只有确定是同一内容才沿用旧 ID；拆分、合并、删除或无法匹配的内容必须显式处理旧引用，不能把批注悄悄挂到另一个段落。修改内容要保留旧引用所指版本或至少保留其原始摘录；旧版本的保留方式由保存实现验证，不能仅靠递增一个数字假定可以回放。

## 扩展与兼容规则

只预留一个可选扩展容器 `extensions`，允许出现在文档、块和列表项上。没有扩展数据时省略整个字段，不填写 `reserved1: null` 等空占位。

```json
{
  "extensions": {
    "example.extractor": {
      "confidence": 0.98
    }
  }
}
```

上述字段仅演示命名空间，不要求实现置信度。扩展键使用提供者或用途的命名空间，扩展内容不能偷偷改变已定义正文、顺序或渲染语义。双语 `translations` 是正式格式字段，不放入 `extensions`；其他影响正确理解正文的能力同样需要进入正式规则。

1. **可以增加可忽略的信息。** 同一 `schema` 内允许增加有明确默认行为的可选元数据；旧消费者可以忽略未知可选字段，但必须在保存时保留它们，包括嵌套的 `extensions`。
2. **不重新解释旧字段。** 改变已有字段的类型、含义、必填条件，或新增旧消费者无法正确表达的正文类型，应增加 `schema`。不需要为尚不存在的变化预设能力协商系统。
3. **不默默丢内容。** 遇到不支持的 `schema`，保留原数据并提示版本不受支持，不进入正常修改保存流程。遇到未知块类型，显示占位并保留原始对象，文档按只读降级处理；不能像当前 EasyRead 渲染循环那样直接略过。
4. **读取宽容，作者输入严格。** 宽容展示历史或未来数据不等于接受不合规范的新转换结果。新的 `reader-authoring-1` 使用独立的字段白名单，未知字段、手写生成身份或错误译文字段应明确诊断；扩展信息进入 `extensions`。已存储文档的未知可选字段仍须往返保留。编译产出还要通过当前存储版本的结构检查；未知类型、重复 ID、断开的资源引用不能算正常完成。
5. **保存必须保留未改的数据。** 修改已知字段时，不能用只包含已知字段的新对象替换整份文档或整块。携带基于哪个 `revision` 的修改，版本不一致时报告冲突，不盲目覆盖较新内容。

## EasyRead 导入与证据

早期设计参考了 EasyRead 的内容模型，其源码和研究测试未随本仓库发布。这不构成对其他版本文件的兼容承诺。

以后确有导入 EasyRead 文件的需求时，保留完整原文件与资源，通过适配器映射标题、文字、公式、图表和来源位置。`en` 在该项目中实际承担原文槽位，`zh` 承担目标译文槽位，必须按实际语言映射到原字段和 `translations`，不能只保留其中一种语言。没有可证实原文依据的旧译文标为来源版本未确认；原数据已缺失的表头或其他原文内容须报告并回到原文件核对，不拿译文冒充原文。`note` 或 `discussion` 中的非原文内容不能混入原文，也不自动成为问题合集。

## 示例与验证范围

持久化格式可以查看已提交的 [Attention 文档](../prototypes/insight-composer/public/articles/attention-is-all-you-need/document.json)。作者输入应使用 [最小作者样例](../services/workspace/authoring-minimal-example.json) 或 [布局范例](../services/workspace/authoring-examples/index.md)，不要混淆存储格式和提交格式。样例及编译通过都不是来源忠实度证据。

当前服务和样本的验证记录由 [文档转换](文档转换.md#验收) 汇总。每次格式或渲染变更仍须按受影响能力检查结构与资源、阅读器呈现、来源定位、MCP 读取/修订及未知字段往返；某一历史样本通过不能代替当前变更的验收。修订边界见 [MCP 文档修订](MCP文档修订.md)。
