# MCP 文档修订

> 本页保留产品约定及带日期的设计背景。早期研究稿、截图和个人待办不随公共源码发布；历史验证描述不代表当前发布包的验收结果。当前范围以根目录 AGENTS.md、现行服务合同及本仓库代码为准。

2026-10-24：正式 MCP 服务版本为 **0.6.0**，目录仍为 32 工具。`read_context` 的 `exact`（省略 `view` 时默认）、`outline` 和 `content` 分别支持精确地址、目录和跨块连续阅读；后两者是有界只读正文投影，不是完整编辑输入。已有文章既可用精确操作修订，也可取得固定版本编辑包，校验并审阅冻结候选后，在原文档 ID 下发布新 revision。具体参数和完整性语义见 [MCP 工具合同](../services/workspace/mcp-management.md)。

2026-10-23：当前公开 MCP 只保留 [32 工具合同](../services/workspace/mcp-management.md)，无旧名称/参数兼容。资料查询用 `query_documents`，洞见维护用 `update_insight`，请求生命周期用 `update_change_request`；合并写入的动作、对象与版本放入 `operation`。正文修订 `revise_document` 和提案决定 `decide_revision_proposal` 保持独立及原有顶层字段、版本检查和幂等回执。

2026-10-21：本地 MCP 修订服务已实现。读取仅通过有上限的 `read_context` 定位；`replace_range` 使用 UTF-16 的 `start` / `end`、`expected_text`、当前正文版本及必要的源指纹修改已读取的小范围文字。完整字段替换仍可显式使用 `replace`，不得用截断摘录覆盖完整字段。修改回执与提案列表仅返回 ID、版本、短变更摘要和状态，完整快照留给阅读器审阅。下方较早日期的未实现说明属于历史状态。

作者侧修订遵循 [Agent 转换约定](Agent转换约定.md)：优先沿用已有块 key 和内部单元 key，提交内容变化及必要对应。工具处理身份、指纹和派生索引；无法确认的旧引用仍按 unresolved 处理。以下持久化字段不要求 Agent 手算。

2026-10-18：schema 2 的 [HTML 块](自定义HTML内容块.md)属于可修订正文。MCP 可读取 HTML、派生文本、内部节点及来源，按节点定位修改 HTML；不能单独编辑派生索引。保存须校验局部 CSS、结构、引用与译文指纹，并原子发布正文和索引，失败保留上一成功版本。本文仍是服务合同，浏览器小样不代表 MCP 正文持久化已实现。

2026-10-17：取消独立正文编辑器的设计与选型。用户在外部 ChatGPT 中说明转换错误或希望补充的内容，由 MCP 读取并修改已转换文档；工作台最多提供具体变更的预览和批准，不建设富文本写作界面。本文定义行为，工具与保存服务尚未实现。

## 修改什么

| 用户意图 | 写入位置与要求 |
| --- | --- |
| 修正转换错误，如漏字、公式符号、表格值或错序 | 修正结构化正文，以原文件为核对依据；原始上传文件保留不变。 |
| 修正或补充译文 | 写入选定语言的 `translations`，校验源内容指纹，不覆盖原文字段；沿用 [双语对照](双语对照.md)。 |
| 把自己的解释、推导或补充加入文章 | 按指定位置插入独立内容块，使用 `origin: "user"`，阅读器和 MCP 均说明这是用户补充；不伪装成来源原文。 |
| 保存批注、问题或笔记 | 写入独立洞见，沿用 [洞见与问题合集](洞见与问题合集.md)，不因此修改正文。 |

“补充到正文”和“保存为洞见”由用户意图区分。普通讨论不写入，问题仍由用户主动添加。正文编辑器的取消不取消洞见已有的手动输入与维护能力。

## 最小修订流程

1. 用户给出文章或位置引用，并说明要纠正或补充什么。
2. MCP 读取当前版本、目标块及必要上下文；需要核对转换错误时，提供对应原页或资源。读取结果包含稳定 ID、`revision`、来源与原／译语言。
3. ChatGPT 按用户要求形成范围明确的修改，区分原文纠错、译文修改和用户补充。`revise_document` 以明确分支表达替换、范围替换、插入、删除和移动；需要完整内容或布局修订时使用下方的编辑包流程。
4. 保存服务校验目标、格式、资源、来源标记和预期版本，完整接受本次修改或返回具体失败。写入成功后返回新版本、变更摘要和可查看的引用。
5. 阅读器刷新对应内容，保留仍有效的阅读位置；重新打开后能看到同一结果。

用户已经给出的明确修改指令可以作为操作依据，不额外要求打开工作台再批准一次。若请求只要求拟稿、尚需选择内容，或 MCP 宿主要求确认，先给出具体的改前／改后与位置，再批准同一份变更。批准所对应的版本或内容变化后不能沿用旧批准；不设计多级审批或另一个编辑器。

## 精确操作与失败恢复

`revise_document` 保留顶层 `document_id`、`expected_revision`、`request_id`、`authorized` 和 `operations`。每项以 `kind` 区分，公开 schema 直接表达必需字段：

| 操作 | 字段与约束 |
| --- | --- |
| `replace` | 文本字段需要字符串 `value`；`head/rows` 单元格需要同时提供零基 `row/column` 和字符串；整个表头或表体需要完整字符串矩阵，不带单元格坐标。 |
| `replace_range` | 精确文字地址、`start/end/expected_text` 和字符串 `value` 均必需；表格单元格另需完整坐标。范围使用 UTF-16，不能切开代理对；不用于替换原始 HTML 结构。 |
| `insert` | 一个完整 `block` 和恰好一个 `before_block_id/after_block_id`。新增用户补充沿用来源标记约定。 |
| `remove` | `block_id`；失去目标的引用保留历史证据，不能猜测新位置。 |
| `move` | `block_id` 和恰好一个前／后位置锚点；身份和来源随块保留。 |

一批操作按顺序执行并原子提交；后续偏移以同批前序操作后的内容为准，不自动重排旧偏移。单项业务错误在可定位时返回零基 `details.operation_index` 和目标地址，整个请求的版本冲突不必归于某一项。翻译仍校验读取得到的 `source_hash`；截断摘录只能用于已核对的范围操作，不能替换完整字段。

工具错误保留业务 `code`，并提供有界 `recovery`：`exact_retry` 重试原参数和原请求 ID；`reread` 先依返回的 `nextTool/next` 重读并核对，改变后的写入才使用新 ID；`repair_input` 修正输入；`request_authorization` 处理实际权限或用户意图要求。`unknown` 表示提交结果未知，包括成功写入后输出校验失败的可能性，必须保留原 ID／载荷，查询结果或原样重试，不能自动换 ID。取消等待或丢失响应也不等于回滚。恢复提示不构成新的写入授权。

## 完整编辑包与已有文章发布

1. 调用 `read_resources(kind:"authoring_artifacts", mode:"editing", document_id, revision?)`，通过返回的授权 URL 下载完整 `reader-editing-package-1`。省略 revision 取当前版本；明确的历史版本导出只复现那个已保存版本。包包含 `base`、可编辑 `authoring`、保存的正文、身份登记、资源与 `resourceBindings` 和往返校验结果。
2. 默认 `mode:"stored"` 返回历史作者输入及 `authoringRevision/matchesDocumentRevision`，可能落后于局部正文修订。编辑包从实际保存的目标版本生成并验证语义／身份／来源指纹；不能无损导出时明确失败，不能回退到旧作者输入覆盖当前内容。
3. Agent 编辑完整 `authoring`、沿用身份 key 与可靠来源，上传 JSON 和必要的新资源。将包的 `base.documentId/revision/documentHash` 映射为 `target:{document_id,base_revision,base_hash}`，传给 `validate_authoring`（可选独立诊断）及 `create_authoring_preview`。目标必须仍是当前正式版本；`base_hash` 不是下载文件摘要或预览摘要。
4. 目标、基准证据、候选正文与资源、身份和引用影响报告随预览冻结。`previous_preview_id` 继续同一草稿并继承目标，不能更换基准。检查原稿、实际 Reader 布局和交互，同时核对受影响身份与引用；删除、拆分和合并不按位置猜重绑，旧 revision／摘录保留，候选中无法匹配的目标标为 unresolved。
5. 通过 `publish_authoring_preview` 提交已审阅的 `preview_id/expected_hash` 和检查记录。发布事务同时检查最新成功草稿、无 `lastError`、精确快照、正式基准 revision/记录，以及受影响洞见／请求／关系引用及其版本的比较交换检查。新增或改变的受影响引用也会使候选过期；重读后重新生成并核对候选，不能自动接受冲突。

成功保存为原文档 ID 的 `base_revision + 1`，保留旧版本、原件和已有业务／同步回执。未改内容身份保留，译文保留来源指纹历史；元数据、计划、洞见、回答、复习和实测阅读事实不从候选旧副本整包覆盖。对象先持久化并校验，再通过既有事务／同步路径提交引用；失败不替换正式文章。字段示例与完整操作见 [作者指南](../services/workspace/authoring-format-reference.md#revise-an-existing-article)。

## 来源、身份与保存

- 修正仍然对应同一来源内容时保留块 ID 和可靠来源映射；谁执行了纠错不改变它是来源内容这一事实。拆分、合并、删除等结构修正必须显式处理受影响的引用和映射，不能把旧批注随意挂到新段落。
- 用户补充使用新的稳定 ID，`origin: "user"`，不填写 PDF 页码或坐标。需要联系原文时可使用已有的内部 ID 链接；位置相邻不表示来源相同。初版将补充放在独立块中，不混进来源段落或原列表项内部。
- 用户补充可以使用已有六种块类型，也可有译文；用实际内容语言填写 `language`，避免直接继承与补充不同的原文语言。来源标记在原文、译文和对照视图中都保留。
- 修改使用读取时的 `expected_revision`；版本不一致时返回冲突并重新读取，不覆盖较新结果。相同请求重试不得重复插入补充或重复递增版本。
- 保存只改明确目标，保留未改内容、资源和未知可选字段；小范围修改不以模型重写整份 JSON 替代。完整修订使用经过往返校验的编辑包与冻结预览，不能用不完整读取或历史作者输入重建全文。结构校验、资源可用性与内容核对分别记录。
- 修改原文字段后保留旧译文，并按源内容指纹标为待核对；修正译文不能顺带改原文或伪造新指纹。
- 每次成功保存递增正文 `revision`，保留可核对的改前内容和变更范围。旧引用无法可靠匹配时保留其摘录并说明失效，不能悄悄重新指向别处。

修订不会修改原始 PDF。来源位置仍描述结构化内容在该 PDF 中的出处；用户补充没有对应原页，行为见 [阅读与 PDF 双向同步](阅读与PDF双向同步.md)。

## 验收

用真实转换结果完成一次正文纠错、一次译文纠错和一次用户补充：MCP 读取正确范围，按指令保存，阅读器显示正确版本，原文件不变。检查未知字段保留、重复请求、版本冲突、译文待核对、旧引用与来源映射，以及未批准或失败的操作没有部分写入。

工作台若提供审阅，只需展示文章与位置、改前／改后和接受／拒绝。验证批准内容与实际保存一致；已明确授权的直接修改不被迫再走一套审阅流程。实施见 文档处理待办 和 MCP 协作待办。

0.6.0 的合同验收另覆盖公开操作分支、`operation_index`、原子失败、连续阅读预算与覆盖、编辑包往返、原 ID 新修订、受影响引用并发冲突，以及未知结果的原请求恢复。注册表生成文档／示例不代替独立维护的 32 工具名称与业务验收；本地合成检查不证明生产模型表现或实际账单。

## 2026-10-21：阅读器内请求更改

快捷键创建的更改请求独立于洞见存储。每条记录包含工作台唯一 `#R00001` 编号、请求版本、文档与正文版本、修改类别、要求，以及可选的精确原文／译文位置。新建、编辑、撤回和恢复走既有原子命令与幂等收据；不会提前改动正文。

MCP `list_change_requests` 可按文档与 pending / cancelled / completed 状态分页读取摘要；`resolve_reference` 支持 R 编号并限量读取请求正文。AI 用 `read_context` 核对目标附近文字后，通过 `revise_document` 处理，同时传入 `change_request_id` 与读取到的 `expected_change_request_version`。直接修订成功或具体提案被接受时，请求与正文在同一事务中更新，记录完成版本；失败、只生成提案、版本冲突或请求已撤回时均不会误标为完成。请求文字不构成脱离当前用户意图的无限授权。
