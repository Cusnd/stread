# 故障排查

[返回 README](../README.md) · [使用指南](GETTING_STARTED.md) · [MCP 接入](MCP.md)

## 先确认运行环境

排查时记录程序版本、Windows 架构、使用 Setup／Portable／源码模式，以及是否指定了独立 profile。正式桌面版本可在“设置 → 更新”查看；默认 profile 为 `%USERPROFILE%\.continuous-reader`。

桌面日志是 profile 内的 `desktop.log`。只提取与问题时间相符的必要片段，隐藏私人文档内容和个人路径。不要公开 `connection.json`、整个 profile、访问令牌或签名私钥。

## 程序打不开或显示“本地资料服务已停止”

先正常关闭残留窗口，再从同一个安装位置打开。确认安装资源未被移动到不同目录，磁盘仍有可用空间，profile 可写。查看 `desktop.log` 中最早的启动错误，而不仅是最后一条退出记录。

如果失败紧跟一次增量更新，重新打开程序以触发上一可用版本恢复。不要先删除 `workspace` 或手工覆盖更新状态文件。若基础安装资源损坏，保留并备份 profile 后重新安装完整版本。

## 打开后资料与另一处不同

检查是否混用了默认 profile、`--reader-user-data` 自定义目录或浏览器开发目录。安装版与 Portable 默认共用 profile；普通浏览器开发通常使用 `services/workspace/.data`，除非设置了 `CONTINUOUS_READER_DATA`。

浏览器的 localStorage 和 sessionStorage 不属于桌面 profile。即使两个服务有相同的文章，偏好或未完成草稿也可能不同。不要通过删除现有目录来“强制重新初始化”；先确认需要保留哪一份数据。

## 原文件已经保存，文章却没有出现

“准备转换”只保存原文件。还需要复制转换请求，让外部 Agent 经 MCP 完成作者输入、预览、独立审阅和发布。Reader 不会在后台自动提取或调用模型。

让 Agent 使用 `inspect_authoring_preview` 查看准确候选、缺失译文和审阅问题。结构校验通过或生成方自检通过，都不能替代独立源文核对及真实 Reader 检查。

## 译文为空、公式不对或来源跳转不准确

语言按钮只显示已保存的译文。先核对当前文章是否已经保存目标语言，随后把问题交给外部 Agent，要求针对当前修订创建并审阅新预览。

报告公式或来源问题时，提供可公开的最小片段、原件页码、正文位置和出现问题的语言模式。内联公式应使用 authoring 合同规定的编码；不要用“校验通过”推断视觉显示正确。

## 原始 PDF 打不开

正式桌面程序使用随包 Python/PyMuPDF 和 PDF.js，不需要另装宿主 Python。检查原文件是否仍在 profile 中、资料是否存在有效的 PDF 来源，以及日志是否报告资源缺失或运行时失败。升级或重新安装前先备份资料。

源码环境检查 `CONTINUOUS_READER_PYTHON` 是否指向可运行且装有 PyMuPDF 的解释器。桌面开发准备失败时，在已配置 `CONTINUOUS_READER_BUILD_PYTHON` 的终端运行：

```powershell
node electron/prepare-python.mjs
```

下载失败时保留错误信息并重试；不要跳过归档或文件哈希验证。

## MCP 提示先打开 Reader，或连接失效

1. 先打开桌面主程序并等到资料库显示完成。
2. MCP 配置的 `command` 使用实际 `Continuous Reader.exe`，参数包含 `--mcp`。
3. 如果主程序使用 `--reader-user-data`，MCP 必须传入完全相同的目录。
4. 主程序重启后，让客户端断开并重连，以读取新的临时连接信息。

桌面 MCP 转发进程不会代为启动 UI 或另建后端。只支持远端 HTTP 的云客户端不能直接访问你电脑的回环服务。更完整的配置见 [MCP 接入](MCP.md)。

## 设置中没有“更新”

普通浏览器与 `desktop:dev` 不显示桌面更新页；开发者通过源码和开发命令更新。旧于 0.1.3 的正式程序也需要先安装一次带更新引导程序的完整版本。

## 检查或下载更新失败

确认能够访问 `github.com`、`api.github.com` 和 GitHub 的发布附件域名。未登录的公开 API 请求可能受限，网络恢复后可重试。程序不会要求提供 GitHub 个人访问令牌。

如果显示签名、哈希、文件清单或兼容性错误，保留当前程序并记录错误，不要手工关闭验证。完整安装版本可从 [Releases](https://github.com/Cusnd/stread/releases) 获取。已经完整下载的更新会保留；中断的传输需要重新下载。

显示“需要更新安装包”表示基础环境变化。使用程序提供的“下载安装包”进入对应的完整版本，安装后仍保留原 profile。不要把 `.crupdate` 文件当作可双击安装的 exe。

## “重启并更新”没有继续

重启前会保存会话、草稿和业务状态。如果保存确认失败且选择了继续使用，程序会保持打开，更新仍留待稍后应用。先处理保存失败原因，再尝试重启；不要为了完成更新而强制结束尚有输入的进程。

## 开发命令失败

| 现象 | 检查项 |
| --- | --- |
| 找不到前端或工作台依赖 | 在根目录执行 `npm ci`，再执行 `npm run setup`。 |
| Node 内置功能或 SQLite 不可用 | 核对实际 `node --version`，需要 24 或更新版本。 |
| `5173` 或 `4177` 已被占用 | 关闭自己的旧开发进程，或一致地调整工作台和代理配置。不要结束不相关程序。 |
| 构建找不到 Python | 设置 `CONTINUOUS_READER_BUILD_PYTHON` 到实际解释器，按[开发指南](DEVELOPMENT.md)验证。 |
| PDF 测试跳过或失败 | 区分缺少准备好的运行时、环境依赖和实际行为失败。 |
| 增量发布提示基础摘要变化 | 检查稳定引导代码、依赖锁、Python、公钥与结构文件；需要时做完整发布。 |
| 生成签名包时找不到私钥 | 普通开发者不持有官方密钥；本地完整打包不需要官方签名私钥。 |

## 提交问题

通过 [Issues](https://github.com/Cusnd/stread/issues) 提供：版本、启动方式、最短复现步骤、预期与实际结果，以及去除私人内容的截图或日志。说明是否发生在干净的测试 profile，并区分自动测试结果与实际窗口行为。

涉及安全漏洞时按 [SECURITY.md](../SECURITY.md) 报告，不要把可利用细节或私人资料直接贴到公开问题中。
