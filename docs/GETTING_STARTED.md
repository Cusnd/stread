# 使用指南

[返回 README](../README.md) · [MCP 接入](MCP.md) · [故障排查](TROUBLESHOOTING.md)

## 安装

当前发行目标为 Windows x64。已发布的 [0.1.3 基础版本](https://github.com/Cusnd/stread/releases/tag/v0.1.3) 使用原名 Continuous Reader：

| 文件 | 使用方式 |
| --- | --- |
| `Continuous-Reader-0.1.3-Setup-x64.exe` | 按安装向导选择位置，之后从快捷方式打开。 |
| `Continuous-Reader-0.1.3-Portable-x64.exe` | 保留在方便访问的位置，双击启动。它会临时展开程序文件，持久资料仍在用户目录。 |

安装包包含 Electron、本地工作台服务和 PDF 运行时，无需另外配置 Node.js、Python、模型账号或固定服务端口。当前源码中的产品名称已统一为 **Stread**；新构建生成 `Stread-<版本>-Setup-x64.exe`、`Stread-<版本>-Portable-x64.exe`，主程序为 `Stread.exe`。新版本是否已经发布，以 [Releases 页面](https://github.com/Cusnd/stread/releases) 为准。

Windows 可能对没有 Authenticode 签名的安装程序显示提示。先核对下载来自 `Cusnd/stread` 的 Releases，以及发布页提供的校验信息。不要通过关闭系统安全功能来处理来源不明的文件。

## Collection：整理资料

Collection 是默认入口。可以按集合、标签和阅读状态筛选资料，搜索资料，并查看详情。

- 单击列表项选择资料并查看详情；双击进入阅读。
- 从详情或菜单将文章加入阅读计划，之后在 Flow 调整安排。
- 归档使资料退出日常列表；可在归档视图中恢复。
- 再次打开文章会恢复已有阅读位置。重新开始阅读是单独的明确操作。

## 导入自己的文件

1. 打开“导入资料”，选择或拖入文件。支持 PDF、HTML、Markdown、文本和结构化 JSON，界面限制单文件不超过 64 MB。
2. 核对资料名称、原文语言、输出语言及转换要求，点击“加入队列”。原文件与任务保存到本机，界面打开 Queue 中的这项任务。
3. 在详情中“复制给 Agent”，或让已经连接本机 MCP 的外部 Agent 直接读取队列。连接方法见 [MCP 接入](MCP.md)。
4. Agent 根据原始材料生成阅读内容，启动另一位未参与生成的审阅 Agent，检查原文、译文和实际 Reader，并修复问题。
5. 审阅后的最新预览按准确哈希发布成功，文章才进入资料库供阅读。

Reader 不会因为上传文件、复制请求或打开文章而启动模型。默认转换非中文资料时，需要完整原文和简体中文；若只要原文或其他语言，请在请求中明确说明。审阅或翻译尚未完成时，应保留候选预览，不能把它描述为已完成的转换。

## Reader：阅读与记录

顶部的“原文／译文／对照”切换已存储的语言内容。没有保存译文时，切换按钮不会代为生成翻译。阅读设置可调整字号、页宽、对照顺序及目录行为。

“原页”用于对照原始 PDF。正文与来源位置的精确程度取决于转换时保留的来源信息；原件可用于核对公式、图表、脚注和版式。

选中文字后，可以通过明确的右键或键盘操作添加洞见。批注、笔记和问题各自保留身份及来源；问题的解答状态与“加入回顾”是独立的。快捷键以“设置 → 快捷键”中的当前配置为准。

左上角返回会回到打开文章的 Collection、Flow 或 Queue，并保留对应视图状态。查看已读文章或编辑洞见不会仅因这次打开而取消已读状态。

## Flow：安排与回顾

| 区域 | 内容 |
| --- | --- |
| 总览 | 最近 7 天或 30 天的阅读活动、阅读记录、计划和待回顾洞见。选择日期可筛选记录。 |
| 洞见 | 集中查找笔记、批注和问题，查看来源、编辑内容与管理回顾状态。 |
| 阅读计划 | 管理下一步要读的文章及顺序。 |
| 阅读历史 | 查看已记录的阅读会话，并回到相应文章或来源。 |

统计来自实际记录的前台阅读活动，不会根据打开文章或保存位置推算历史时长与完成率。

## Queue：管理 AI 任务

Queue 与 Collection、Flow 同级。左侧按源文件转换、内容纠错、译文修改、问答和通用任务筛选；主体按待处理、需处理、已完成查看，已撤回任务在左侧单独查看。

- 点击任务就地展开要求、来源及结果。`#T00001` 这类编号可复制、搜索，也可用顶部编号查找入口打开。
- 通过“添加任务”选择已保存的源文件或文章；问答选择已有的未回答问题，普通问题不会自动入队。内容纠错、译文修改和通用任务复用文章更改请求，保留原 `#R` 身份。
- 任务可编辑、撤回和恢复，编号保持不变；编辑会推进版本。关闭编辑面板后，未提交的输入保留在本标签页。
- 源文件转换可以在文章存在之前入队。PDF 详情显示实际原件首页，默认非中文输出完整原文和简体中文，也可明确选择仅原文。
- 读取或复制任务不会启动 Agent，也不会把状态改成处理中。待审阅修订、冻结转换预览及失败诊断会显示在需处理视图；实际回答、应用或发布成功后才显示完成。
- 从任务打开 Reader，再返回 Queue，会恢复筛选、选中项与列表位置。

队列保存在同一个本地资料库。现有更改请求会幂等关联任务编号，原文件、原请求、问题与历史结果仍保留。此节描述当前源码功能，已安装发行版是否具备该页面取决于其版本。

## 更新程序

在正式桌面程序中打开 **设置 → 更新**：

1. 点击“检查更新”。此操作访问公开 GitHub Releases，不需要 GitHub 账号。
2. 有更新时点击“下载更新”，可查看实际下载体积和进度。
3. 下载完成后点击“重启并更新”。程序先完成现有保存流程，再停止本地服务并重启。

如果保存失败并选择继续使用，更新不会强制应用。已完成的下载会留在本机，下次打开后仍可重启应用。

匹配差分基线时只下载变化的程序文件；跨过版本时下载完整程序层包，仍复用本机 Electron、Python 和生产依赖。基础运行时、更新引导程序、签名公钥或数据库结构等变化，需要完整安装包；“下载安装包”会打开相应的完整发行版本页面。

更新包经过签名和哈希校验，在独立版本目录组装，通过重启切换。新版本未通过启动检查时，下次启动恢复上一可用程序。程序回退不会撤销用户资料修改，也不能替代备份。

0.1.3 之前的版本需要先安装一次完整基础版本。设置中的更新入口只存在于正式桌面程序；源码开发窗口通过源码更新。

## 数据位置与独立资料库

默认 profile 为 `%USERPROFILE%\.continuous-reader`：

| 内容 | 位置 |
| --- | --- |
| 数据库、正文对象、原文件和资源 | `workspace` |
| 草稿与桌面会话快照 | `reader-session.json` |
| 窗口状态 | `desktop-state.json` |
| 偏好与浏览器存储 | `Local Storage` 等 Chromium 目录 |
| 增量程序版本与更新状态 | `updates` |
| 诊断日志 | `desktop.log` |
| 当前本机服务连接与临时令牌 | `connection.json`，正常退出后清理 |

安装版与 Portable 默认共用此 profile。需要独立资料库时，使用实际安装路径并显式指定目录，例如：

```powershell
$readerExe = 'C:\Apps\Stread\Stread.exe'
$profile = Join-Path $env:USERPROFILE 'ReaderProfiles\Work'
& $readerExe "--reader-user-data=$profile"
```

示例中的安装路径需要替换。每个独立 profile 都有自己的资料和偏好，不会自动交换或同步内容。MCP 客户端必须指定同一个 profile。

## 备份与恢复

1. 正常关闭程序，等待保存和退出完成；同时断开其 MCP 客户端。
2. 将整个 profile 复制到另一个安全位置。保留 `workspace` 中的数据库、`objects`、`blobs` 以及会话和偏好文件。
3. 恢复时先把备份复制到一个新的目录，用 `--reader-user-data=<该目录>` 打开并核对文章、原页、洞见和草稿。
4. 确认恢复正确后再决定使用哪份资料，保留原目录。不要同时运行同一份备份的两个副本。

不要在程序运行时只复制单个 SQLite 文件；已提交数据可能仍在 WAL 中。不要把资料库放进安装资源、`.desktop/runtime` 或发布产物目录。新旧版本之间的数据库兼容性以相应发行说明为准。

分享问题报告时不要附上 `connection.json`、完整 profile 或含私人原文的日志。需要诊断的内容见[故障排查](TROUBLESHOOTING.md)。
